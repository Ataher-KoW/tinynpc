# TinyNPC v1.0: local NPC dialogue for games

## [▶ Watch the demo: baseline vs v1.0 (1 min 45 sec)](https://github.com/Ataher-KoW/tinynpc/releases/download/v1.0/tinynpc-baseline-v1.0-demo.mp4)

I wanted small NPCs I could actually talk to. This is the newest student fine-tune, chosen after trying it in my game. It is **1.28 GB**, runs locally, and takes the character description, player message, memory and visible scene facts as context.

Only the student model and developer integration are included. Bring your own game and speech services. POV means structured observations supplied by your game, not raw image understanding.

## Try it

Windows x64, NVIDIA GPU, Python 3.10 or newer:

```powershell
git clone https://github.com/Ataher-KoW/tinynpc.git
cd tinynpc
python -m inference.setup --runtime windows-cuda
python -m examples.chat
```

Setup downloads ten checksum-verified parts and assembles the model. The native runtime downloads separately. Allow 6 GB free during setup. Existing users should pull the new source and rerun setup; v1.0 uses a new model filename, so it does not overwrite the previous weights.

Define your NPC with the JSON examples in [the character guide](https://github.com/Ataher-KoW/tinynpc/blob/main/docs/characters.md). Add your game's visible entities and the player's message. See [Python and HTTP integration](https://github.com/Ataher-KoW/tinynpc/blob/main/docs/integration.md).

## Baseline vs v1.0

The comparison below uses the previous in-game baseline from the final training run, not the older published v0.1.0 weights. Both models have the same 1.28 GB file size. v1.0 gives more developed replies and won more of the AI-rated conversations; the baseline remains faster on average.

[Watch the 105-second side-by-side demo](https://github.com/Ataher-KoW/tinynpc/releases/download/v1.0/tinynpc-baseline-v1.0-demo.mp4). Seven comparison slides show the same player prompt with the baseline reply on the left and v1.0 on the right, including awkward, out-of-the-box and out-of-place questions. Each reply includes its measured warm generation time. Intro, eased transitions and a closing tradeoff note frame the comparison. Exact outputs are attached as paired-responses.json.

Measured on my **RTX 2060 6 GB**. Warm text inference only: model loading, speech recognition and speech synthesis are excluded. Other hardware is unmeasured.

| Development measurement | Previous baseline | v1.0 preference fine-tune |
|---|---:|---:|
| Model file size | 1.282 GB | 1.282 GB |
| Conversations preferred by AI judge | 1 | 51 |
| Tied conversations | 48 | 48 |
| Mean reply time, 100 scripted conversations | 0.383 s | 0.494 s |
| Mean reply length in that test | 8.50 words | 15.25 words |
| Failed conversations in that test | 1 | 0 |

The whole-conversation AI preference score was **0.750**, calculated as `(51 wins + 0.5 * 48 ties) / 100`, with one loss. The family-bootstrap 95% interval was 0.694 to 0.813. This is a development result from an AI judge, not a human-quality percentage or an independent final benchmark. The teacher also contributed training data. There are no blinded human preference scores.

### Additional diagnostics

The separate 320-turn stress test had zero generation failures for both models, with every measured reply below one second. Complete-reply p95 was 0.464 seconds for the baseline and 0.670 seconds for v1.0. Short-reply p95 was 0.380 versus 0.587 seconds. Narrow corrected-name/current-view checks passed 24/24 versus 19/24. These results explain why the automatic gate kept the baseline; I chose v1.0 after playing with it myself.

Those checks are literal, not overall conversation quality. Repeated scripted turns are correlated. A result under one second here is not a guarantee for every prompt or machine. [Machine-readable statistics](https://github.com/Ataher-KoW/tinynpc/blob/main/benchmarks/v1.0/statistics.json) retain all results.

The 600-case test elsewhere in the completed run evaluated the automatically selected baseline, not these preference weights. Older IFEval, quality and speed graphs belong to earlier models and must not be attributed to v1.0.

## Demo and files

The release includes a 105-second baseline/v1.0 comparison and its exact paired transcript. Both captures use the same current runtime, frozen scene, seed and separate temporary memory. The displayed timings use 20 GPU layers on RTX 2060 6 GB and measure each warm generation call, including retries. They exclude loading, speech and scene/memory preparation. These are single captures, not repeated controlled speed tests, and should not be compared directly with the full-GPU development benchmark. The ending explains my choice: I sacrificed some inference speed to make it feel more realistic and have better conversations. The game and audio services were not my focus. I made a simple game to show the model. Demo pacing is edited for reading; it is not a continuous latency benchmark.

Model size: **1,282,438,944 bytes**, or 1.282 GB / 1.194 GiB. The manifest and SHA256SUMS.txt identify the exact weights and each download part. No teacher or speech weights are shipped.

Code: MIT. Modified student model: Apache-2.0. See the model card and model license attached to this release. The model can still invent details, forget corrections and give awkward replies. Keep important game state under your game's control.

Both published versions remain available: [v0.1.0](https://github.com/Ataher-KoW/tinynpc/releases/tag/v0.1.0) and [v1.0](https://github.com/Ataher-KoW/tinynpc/releases/tag/v1.0). The earlier release is preserved, but is not the internal baseline in this comparison.
